# V0.3 / M1 + M2a + M3 前端

## 运行

在仓库根目录运行同源后端：

```powershell
python -m repo_agent.task_http --port 4176 --workspace-root experiments/tasks
```

打开所选空闲端口（上例 http://127.0.0.1:4176 ）。服务默认使用 `runs/tasks/projects.json` 本机项目配置与 `runs/tasks` 任务目录。配置格式和校验规则见 [接口契约](../docs/v0.3/task-api.md)。未配置项目时页面禁用提交，不会借用演示项目。4173 为旧静态服务、4175 为旧 M1 服务，不停止或复用。旧进程不会加载新接口；M2a 须另选空闲端口启动当前版本。端口占用时换端口，不接管未知服务。

不再用 `python -m http.server` 运行真实保存流程：普通静态服务不提供 API。前端仍采用无第三方依赖的 HTML/CSS/JavaScript，服务仅需提供 index.html/styles.css/app.js。

## 已实现

- GET `/api/projects`：真实项目列表、加载/空列表/失败状态、重新加载。没有可用项目时禁用提交。
- 真实任务表单：起始版本、当前/期望行为、允许修改路径（每行一项）、测试权限、固定 pytest 目标（每行一项）或明确暂不检查。默认 maxSteps=12。
- 核对弹窗后 POST `/api/tasks`：JSON 只含契约字段，不发送项目本机路径或前端自造 ID；保存期间禁用重复提交。字段/版本错误显示可读原因，保留表单。
- 成功跳转 `/#/tasks/<完整32位ID>`，详情重新 GET，展示真实保存、尚未启动、准确 commit、创建时间（北京时间）、预算与约定。刷新只查询，不再次 POST。
- 不存在、记录损坏、存储/后端不可用分别显示接口错误，不伪造空记录或成功。
- POST 网络失败或成功响应无法确认时，显示“保存结果暂无法确认，勿直接重复提交”，本页面会阻止重发，不自动重试。后端没有幂等键/历史列表，需由维护者核对；刷新会重置浏览器内存状态，不能以刷新当作安全重试手段。
- 页面代次和项目请求序号避免旧响应覆盖新页面/新项目列表。POST 一经发出即使用户导航离开也不意味着取消后端保存。
- 演示表单位于 `#demo`，演示执行/结果与真实详情分开；演示填充不进入真实创建流程。下载草稿目前只在演示表单提供。
