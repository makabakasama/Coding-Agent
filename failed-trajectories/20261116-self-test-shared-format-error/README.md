原始实现片段如下，代码块中的 raw string 含两个实际反斜杠。

```python
def _print_Trace(self, expr):
    return r"\\operatorname{tr}\\left(%s\\right)" % self._print(expr.arg)
```

模型编写的完整检查如下。

```python
from sympy import MatrixSymbol, Trace, latex

A = MatrixSymbol('A', 3, 3)
assert latex(Trace(A**2)) == r'\\operatorname{tr}\\left(A^{2}\\right)'
```

两处都把 LaTeX 命令写成双反斜杠，并采用相同的 operatorname 与括号格式。实现递归调用 `self._print`，内部平方的格式发生了变化，但这条断言接受了外层错误格式。

官方评分随后在新容器中应用同一补丁。`test_trace` 第一条断言要求如下，raw string 中各命令前为一个实际反斜杠。

```python
assert latex(trace(A)) == r"\mathrm{tr}\left (A \right )"
```

## 错误测试为何通过

断言的预期与实现采用了相同错误格式，轨迹没有记录这个预期的独立依据。该检查能证明当前实现与模型选定的字符串一致，却无法据此确认字符串符合任务和项目约定。

现有完成校验确认了当前业务版本具有通过的开发检查，所引用的工具结果也真实存在。本次暴露的是测试预期的正确性缺口。原始轨迹支持“共享错误预期”的判断，无法证明模型生成断言时的内部思考过程或复制方向。

## 正确的测试流程

1. **先确定预期依据。** 从任务说明、公开 API 文档和仓库现有格式测试中确定行为，再写断言。记录预期来自哪里。需求没有明确的格式应先核对项目惯例，仍有歧义时说明假设或澄清。精确输出属于兼容契约时，同时检查命令、转义、括号和空格。
2. **先验证测试能识别缺陷。** 在固定 G 上运行新增回归，确认它因目标输出错误而失败，记录实际值与预期值的 repr。导入、依赖和环境错误应先排除。冻结断言及其依据，再修改实现。
3. **用已知错误补丁检查测试有效性。** 本案例可以将保存的错误 P 作为反例，要求同一测试拒绝双反斜杠及错误外层格式。如果这个错误 P 仍能通过，就重新审查断言和需求依据。需要调整预期时保留理由与版本。
4. **修复后运行目标与相关控制测试。** 覆盖 Trace(A) 和任务提出的 Trace(A**2)，既检查外层格式，也检查内部表达式的递归打印。再次编辑业务代码后重跑受影响检查，记录补丁哈希与测试版本。
5. **独立评分。** 保存业务补丁 P，在新环境恢复同一 G 与冻结 R，核验来源，先复现 G+R 的目标失败，再应用 P 执行目标与控制测试。保存实际输出、逐题报告及失败分类。官方隐藏断言继续由评分端保管，本页摘录只供事后分析和评测方审查。
6. **按证据报告结果。** 分别记录模型自报完成、开发自测结果和官方任务结果。本案例结论为“自测通过，官方任务失败”。后续修复需产生新记录，保留本次失败轨迹。

上述是后续应采用的流程。本次运行复用了此前固定 G/R 基线，没有在本次评分应用 P 前重新执行基线。此轮未运行改进后的测试，也未验证推荐断言能够拒绝错误 P。

将本案例用于后续模型评价时，需要区分原始隐藏测试场景与已知测试的定向修复。把本页官方断言提供给同题模型后产生的结果，应记录为已知测试条件下的修复。
