# 项目成员与执行审批实施记录

2026-11-24（北京时间）。本记录描述第二批实现与静态核对。后续测试结果和验收边界见[第二批验收](project-access-acceptance-20261124.md)。

## 本批实现

- 实例管理员从已有本机项目登记中选定仓库和首位维护者。PostgreSQL 记录同一工作台下的项目、仓库路径和成员角色。相同或重叠目录不可作为不同授权项目同时启用。变更成员时锁定项目行，移除或降级最后一位可用维护者会回滚。本机账号禁用仍由实例管理员处理。
- 网页和任务 CLI 使用同一 HTTP 鉴权。任务按其数据库项目归属校验，Chat 按原会话项目或无项目会话的创建者校验。旧的无主会话保留给实例管理员查看。非成员直接读取项目资源返回 `404`，成员操作超出角色返回 `403`，未登录返回 `401`。全局任务和 Chat 列表按权限缩小读取范围，Chat 在筛选后分页。SSE 按当前会话和成员权限复核，成员看到事件摘要和回复材料。
- 普通任务、Chat 编码及基于选定交付返工都进入项目的执行申请。申请保存发起人、项目、需求和完整执行设置。Chat 返工还保存父任务和补丁标识。提交申请只写申请记录。实例管理员放行时复核发起人、成员权限、项目仓库和冻结范围，在同一事务写入决定和对应队列，重复放行返回已保存的决定和任务或 Chat 轮次编号。普通任务隔离副本可在放行时准备。
- 角色管理、执行申请列表、决定与进度入口已接入项目页面。旧的本地单用户模式沿用原启动路径。任意本机路径登记、敏感诊断、撤回、永久清理和真实实验启动仍需实例管理员权限。旧记录保留原关联信息。待放行的 Chat 申请若遇到会话版本变化，审批按原版本前置条件失败，可拒绝旧申请后重新提交。

## 验收场景

| 场景 | 核对依据 |
| --- | --- |
| 同一账号在 A 为开发者，在 B 为观察者 | 分页和列表仅显示可读资源。能提交 A 的申请，不能提交 B 的申请或读取第三个项目的材料。 |
| 热缓存、事件流与撤权 | 先命中缓存并打开 SSE，再移除成员。下一次直接读取返回 `404`，在途流关闭，重连被拒绝。 |
| 提交、拒绝和放行 | 普通任务、Chat 编码及返工申请对照冻结设置。申请与拒绝前后均无该请求对应的任务调度或 Chat 队列记录。放行后可追到唯一记录。 |
| 放行前撤权和并发放行 | 撤销申请人角色或禁用账号后放行被拒绝。两个实例管理员并发放行同一申请，只写一条队列记录并返回同一执行或轮次编号。 |
| 最后一位维护者并发变更 | 对两个维护者同时移除或降级，最终仍有可用维护者。 |
| 旧入口与数据兼容 | 本机单用户模式仍能直接入队，实例管理员能读取旧无主会话，其他账号无法访问。 |

Worker 领取时复核以及跨提交、执行和审查的完整审计属于第三批。第一批已有验收记录只反映当时的账号门禁实现。
