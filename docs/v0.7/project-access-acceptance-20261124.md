# 项目成员与执行审批验收

2026-11-24（北京时间）。第二批定向验收通过。后端及 CLI 21 项、前端离线 67 项、真实 Edge 4 组通过。数据库和缓存使用本机 PostgreSQL 与 Redis，测试数据隔离。

| 验收项 | 实际结果 |
| --- | --- |
| 项目与会话隔离 | 同一账号在 A 为开发者、在 B 为观察者，列表和 Chat 分页只返回可读记录。B 的执行申请返回 `403`，第三个项目的任务、事件和材料入口返回 `404`。新无项目会话仅本人可见，旧无主会话仅实例管理员可见。 |
| 热缓存与 SSE 撤权 | 读取任务并确认 Redis 有缓存，随后移除成员。缓存仍在，业务读取返回 `404`，已经打开的 SSE 关闭，重连返回 `404`。登录会话仍有效。 |
| 普通任务和并发放行 | 待放行时未创建工作副本或队列记录。维护者无放行权限。两个实例管理员并发放行均得到同一执行编号，PostgreSQL 只新增一条调度记录。Edge 中可看到申请、放行和队列进度。 |
| Chat 和返工 | Chat 申请先冻结 commit，分支前移后重复提交仍取回原申请。并发放行只写一条 Chat 队列记录。返工用例以脚本模型生成了非空 Diff，维护者可以接收交付，返工轮次保存原父任务和补丁标识。Edge 中可完成 Chat 申请和放行。 |
| 拒绝、放行前撤权和最后一位维护者 | 拒绝、降级和禁用申请人的场景均未入队。两个维护者被并发降级或移除时，一个请求返回 `409 LAST_MAINTAINER`，最终保留一位可用维护者。 |
| CLI、旧入口和实机撤权 | CLI 通过同一 API 提交和放行，凭据库存取由替身覆盖。旧单用户模式仍可直接入队。Edge 中移除成员后，其原有任务页重新读取时被拒绝。 |

## 验收中发现的问题

- 旧任务执行在序列化后的 JSON 上替换敏感字符串，可能破坏数字字段，使 `RecordedAgent` 抛出 `JSONDecodeError`。已改为对结构化数据中的字符串脱敏。已验证数字字段保留、字符串中的敏感值被替换，旧任务 CLI 重跑未出现该异常。
- 一次返工重试只替换了模型工厂，执行来源仍指向配置的 Provider，触发了至少一次未授权的真实模型调用。该运行未计入通过结果，调用次数和费用未核对。复跑夹具显式使用脚本模型，并拦截任务和 Chat 对配置 Provider 的实例化。Edge 走查无 Worker 领取任务。
