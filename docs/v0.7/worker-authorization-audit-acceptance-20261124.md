# Worker 领取授权与执行审计验收

2026-11-24（北京时间）。第三批定向验收通过。本轮使用实际 PostgreSQL、Redis、隔离项目夹具与脚本模型。任务和 Chat 的真实 Provider 初始化及模型 HTTP 请求均被拦截。

| 验收项 | 实际结果 |
| --- | --- |
| 普通任务放行后撤权 | 降级申请人、禁用申请人和禁用审批人分别得到对应原因。独立 Worker 进程领取被拒绝，工作副本未准备，业务文件无改动，未调用模型。 |
| Chat 两段领取 | bridge 领取前移除成员，未生成编码任务。bridge 通过后禁用申请人，编码队列拒绝领取，Chat 回写同一拒绝原因，两种情况均无模型调用。普通讨论按提交人权限复核。 |
| 冻结范围与历史兼容 | 更改冻结契约或清空队列授权依据后，账号模式下拒绝领取。通过审批的 Chat 返工在 bridge、编码队列、结果和审查中保持同一个 `executionId`。 |
| 并发与数据库失败 | 分别控制撤权和领取先提交。撤权先提交时领取被拒绝，领取先提交时保持已领取。注入 PostgreSQL 语句失败使领取事务回滚，返回 `503`，队列仍待领取且没有虚假的复核或拒绝事件，复试可领取。 |
| 终态恢复 | 注入完成回写失败，保留已落盘的终态文件。独立 Worker 启动时补齐 PostgreSQL 终态和审计。重复恢复未再次启动模型或追加重复完成事件。 |
| 审计与浏览器 | 用一个 `executionId` 查出申请人、审批人、Worker、拒绝或结束原因、审查人和补丁 SHA256。重复提交同一审查结论只保留一条审查事件。非成员查询返回 `404`。实际 Edge 从撤权终态打开审计页，核对人物和原因。 |

## 结果与边界

- 后端集成及传输回归共 **29 项通过**。合并用例 28 项通过，领取回滚用例独立运行 1 项通过。其中第三批专属用例共 11 项。
- 旧任务 CLI 独立重跑 **3 项通过**，前端离线 **67 项通过**，Edge 审计页 **1 组通过**。
- 首次运行修正了 PostgreSQL 保留字列名和 Chat 测试预算对象缺少 `count()` 的问题。一次合并运行中，旧 CLI 的执行线程超过 20 秒等待，Windows 当时仍持有临时锁文件。独立重跑通过，未定位超时原因。残留测试目录已清理。
- 数据库故障与回写失败分别通过 SQL 语句错误与故障注入验证。真实模型调用为零。验收没有用生产仓库执行任务。已核对专用测试数据库清理，脚本和原始输出保存在本机忽略目录 `runs/worker-authorization-acceptance-20261124/`。
