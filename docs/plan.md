## 项目目标

面向 Python 后端 / AI 应用开发求职，形成可演示、可解释、可核验的简历项目。

项目同时交付后端服务和 Coding Agent。后端负责接收任务、可靠调度、状态查询与结果交付；Agent 负责仓库修改、公开检查与补丁生成。后端验收考察任务在并发和故障下的交付行为，Agent 求解能力沿用[冻结阶段的评测口径](v0.6/harnesstax-outcome-plan.md)。

两条主线：**以 Chat 为入口的 Agent 工作台，以及 Agent Evaluation。** Chat 负责持续交互，Agent 负责执行，coding 是工具能力；用户在同一会话完成问项目、讨论需求、授权修改、查看结果和追问。

### 首批实施顺序与验收口径

1. **建立账户。** 在 PostgreSQL 增加账户表，唯一约束作用于规范化后的登录名。保存密码的 Argon2id 哈希、账户状态和会话版本。首个管理员通过本机命令创建，密码由交互提示读取。禁用账户时，在同一事务更新状态、递增会话版本，确保重新启用也不会恢复旧会话。
2. **接通服务端会话。** 提供登录、查询当前身份、退出三个 HTTP 入口。登录成功后签发随机会话标识，Redis 按标识摘要保存账户 ID、签发时的会话版本和过期时间。受保护请求同时核验 Redis 会话以及 PostgreSQL 账户状态、版本和单会话撤销记录。退出删除当前 Redis 会话，提交该会话摘要与原过期时间后才返回成功。后续退出会清理已过期的撤销记录。失败计数与过期时间在 Redis 中原子更新，登录名不存在和密码错误返回一致的认证失败响应。
3. **接入现有调用方。** 在 HTTP 公共入口先完成身份校验，再进入 Chat、普通任务、历史和材料路由。前端通过统一请求函数处理登录失效和写请求 CSRF 令牌；CLI 使用同一登录契约。SSE 在连接及重连时校验身份，禁用后在下一次服务端检查时停止发送。Worker 保留独立进程身份，排队任务的发起人和领取时授权安排在第三批。
4. **分阶段开放业务。** 首批允许普通账户登录、查询身份和退出。项目成员授权接入以前，仓库读写、任意路径登记、任务调度和历史材料只向管理员开放。首次启用账号模式时显式创建管理员；数据库或 Redis 会话服务不可用时返回服务不可用。已有 RedisCache 对读取缓存故障会回源，认证路径需要区分“会话无效”和“存储不可用”。

首批验收使用管理员、普通账户及两个独立客户端，记录登录、退出、到期、禁用后重新启用、Redis 短暂不可用及 CLI 访问的实际结果。未登录访问业务资源预期为 401；有效普通账户访问尚未开放的管理员资源预期为 403；会话存储故障预期为 503。通过标准包括旧会话不能复活、退出一个客户端不影响另一个客户端、被拒绝的任务提交没有生成调度记录。登录名、密码、Cookie、CSRF 令牌按各自敏感度处理，原始凭据不进入验收材料。涉及项目角色或 Worker 撤权的用例分别在第二、三批验收。

2026-11-24，首批定向验收通过，包括真实 Edge、Windows 凭据库和 Redis 连接中断恢复。复跑集成用例时，为验收进程配置专用的 `CODING_AGENT_TEST_DATABASE_URL` 和 `CODING_AGENT_TEST_REDIS_URL`，运行 `python -m unittest tests.test_workbench_auth tests.test_chat_stream_transport`。结果、环境和证据边界见[首批验收记录](v0.7/account-auth-acceptance-20261124.md)。
