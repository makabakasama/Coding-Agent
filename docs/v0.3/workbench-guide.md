# V0.3 工作台使用指南

命令行管理同一批任务见 [统一任务 CLI](task-cli.md)，新建、轮次、准备、启动和结果均调用本工作台后端。

更新日期：2026-11-02。本文描述当前实现；M1/M2a/M3 运行说明保留各批次当时状态。

新普通任务现已分为需求和运行轮次。保存表单创建需求及首轮；进入“项目与需求”选择该需求，可查看全部轮次并点击“准备新一轮（不启动模型）”。进入新轮次后仍须分别准备副本、确认执行。新记录位于 `runs/<taskKey>/run_<轮次ID>`，工作副本位于对应项目的 `experiments/<project>/workspaces/`；旧任务记录原位兼容，旧任务暂不猜测关联需求。接口见 [多轮约定](ordinary-rounds-api.md)。

## 启动

在项目根目录使用已经准备好的环境：

```powershell
.\.venv\Scripts\python.exe -m repo_agent.task_http --port 4176 --workspace-root experiments/tasks
```

打开 [工作台](http://127.0.0.1:4176/#task)。服务启动不调用模型；普通任务的启动确认、固定实验的启动确认才触发执行。源码变化需要重启服务，重启前先确认没有运行中的任务或实验。

服务应在普通用户终端运行，不要从限制 `.git` 写入的 Agent 沙箱中启动长期服务，否则后台 Git 创建 worktree 也会继承限制。2026-11-03 的准备轮次 `20261103-095336_886357fb` 已明确记录 `.git/worktrees/... Permission denied`，随后服务改由沙箱外的当前用户进程启动；没有更改目录 ACL，也未重试或重置该轮。此环境问题不由重复新建轮次解决。只读页面能访问不表示服务具备创建副本所需权限。

新克隆不包含本机配置、环境或实验材料。普通任务项目配置位于 `runs/tasks/projects.json`，基本配置见 [M1 项目配置](runbook.md#2-项目配置)，执行解释器配置见 [M3 运行说明](m3-runbook.md)。Provider 沿用本机既有配置，不在网页输入密钥。不要把空历史列表误认为材料已从 Git 恢复。

## 普通任务

1. 在任务页左侧选择项目和任务类型：阅读代码、修复 Bug 或补充小功能。
2. 填写起始版本、背景或当前行为、期望分析或行为。保存时会解析准确 commit，源仓库未提交改动不会进入副本。
3. 修复和功能任务填写允许修改的相对文件或目录，每行一个；阅读任务禁用该输入，后端也禁止编辑。
4. 若启用测试，填写固定 pytest 文件或测试节点，每行一个；否则结果保留未运行测试的事实。
5. 预览并保存。进入任务详情后先准备独立副本，再确认启动 Agent。
6. 页面显示步骤和实际反馈。结束后查看 Agent 总结、修改文件、diff、固定检查和范围审查；它们分别表示不同证据。
7. 从 [普通任务记录](http://127.0.0.1:4176/#tasks) 重新打开同一任务。刷新只查询，不重发启动请求。

阅读任务的交付在“Agent 总结（说明）”和工具记录中，无 diff 是正常情况；总结正确与否仍需结合源码审查。三类示例及离线检查见 [三类任务流程](three-task-flow.md)。

## 两个固定实验

任务页右侧“已有实验项目”进入固定需求：

- [browser-use #5998](http://127.0.0.1:4176/#projects/browser-use/tasks/browser-use-5998)
- [pydantic-ai #10525](http://127.0.0.1:4176/#projects/pydantic-ai/tasks/pydantic-ai-10525)

需求页可以浏览已有轮次；读取历史不调用模型。要开展新实验，找到“运行控制”，点击“开始新一轮真实实验”，核对后“确认启动”。这会使用已有 Spec 的固定 G、冻结 R、环境、业务范围和独立验收流程，不能通过网页随意更换这些配置。

新轮次返回后进入详情，查看准备、Agent、补丁导出及 verify 报告。`agent_reported_finished` 只说明模型停止；独立验收应查看对应 verify 报告。原报告记录的哈希与本次重新校验哈希不同，历史接口的 `not_checked` 不表示已经核验原件。

## 结果不确定与限制

启动响应丢失先查询状态，不重复点击启动。普通任务重启后可能显示 unknown；固定实验运行控制只保留当前服务进程的最近记录，重启后应从需求轮次列表找回落盘材料。服务重启不提供继续执行能力。

普通任务执行卡片新增“异常恢复”：先核实遗留占用，再打开旧执行与诊断；后端确认没有关联活动执行后，才允许手动解除。解除保留旧材料，不恢复模型、不重跑旧轮。步数上限会进入终止与结果整理，常规落盘失败时尽量保存独立终止凭据，并明确部分交付。规则见 [执行恢复](execution-recovery.md)。

当前仍没有取消、续跑模型或网页追加独立验收入口。普通任务每个运行编号只执行一次，再次执行从需求页新增轮次；改变需求须新建需求。固定实验也在原需求下追加新轮次，继续使用原实验语义。新写入已采用统一层次，旧材料保持原位。Worktree 隔离文件，不是执行沙箱。
