# 冻结仓库测试准入验收

2026-11-20。Benchmark 原来用写保护的文件名和目录规则判断能否执行测试。RC1 在 pytest 5221 中六次被拦在测试启动前，其中包括基准提交已有的 `TestShowFixtures`。源码位于 `testing/python/fixtures.py`。

## 实施

- Benchmark 从固定 Git tree 读取普通 Python blob，静态识别测试函数和类，或核对显式授权的目标。文件、类和用例仍交给已配置的测试运行器，模型提供的值只占目标参数。可链接路径、普通业务文件、无效选择器和非冻结测试均不能进入运行器。
- 已识别的冻结测试在编辑前就受保护。导出时独立审查实际候选补丁，测试改动和重命名、复制需人工审查。既有测试及配置写保护继续生效。工作台任务和 Chat 继续使用其已授权的 `checkTargets`。
- 动态生成或继承的用例在无法从固定源码直接识别时，需要显式授权。现有冻结运行、评分组件和官方报告保留。新求解源码纳入未来注册时需要生成对应版本清单。

最终定向套件 89 项和 23 个子检查通过。重命名、编辑、变更后执行和导出边界另做了一次定向检查并通过。两份归档日志 SHA256 和冻结评分控制文件指纹均已复核。

## 调试反馈试验

通用控制流样例针对同一个用例运行基线、首次编辑与二次编辑。首次编辑误删分支，基线和候选抛出不同的异常。离线原型将两条异常、最近 diff、候选哈希和日志引用合并到测试回执，通过真实对话组装送达下一轮。脚本恢复分支后同一命名用例通过。该结果验证了反馈的传递与复验链路。

scikit-learn 12471 的原请求已经包含相关 diff 和两条异常，本次用脚本选择二次编辑。集中反馈是否能改变真实模型行为、修复准入是否提高官方解决率，均待独立实测。集中反馈未启用到生产，收尾策略和预算沿用已有设置。
