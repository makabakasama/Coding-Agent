# P0 收尾请求与预算验收

## 根因与实现

旧规则按最大输入窗口、普通输出上限和传输尝试次数为收尾预留。即使运行中还够发多次请求，只要下一次普通请求加上这笔预留超过总额度，系统就切到只允许 `finish`。进入收尾时，旧请求仍携带本轮执行对话和工具结果。

- `repo_agent/evaluation/runner.py` 用已记录的任务与进度构造短请求，按该请求输入及工具定义的估算、最多 1024 输出 token、每次 128 token 安全余量和最大传输尝试次数预留。调用前执行总预算准入，调用后按可用的 Provider 用量或保守估算结算。Provider 报告超出预估时记录差额，累计超出硬限时终止。
- `repo_agent/core/progress.py` 保存最近检查的版本、目标、分类、原因和证据编号。已有完整执行轨迹继续保留。收尾仅携带任务摘要、近期文件与编辑动作、最近检查、未完成计划和完成校验结果。
- `repo_agent/core/agent.py` 复用原完成校验。预算不足、模型失败、收尾被拒或达到决策上限时，保存代码生成的结构化 `incomplete` 报告，无需额外模型调用或成功的仓库工具调用。
- `tests/test_swebench_adapter.py` 与 `tests/test_evaluation_checks.py` 覆盖只收尾请求、结算、模型失败、非法工具、计划不一致与检查结果的传递。

预算触发的收尾依然只提供 `finish`。普通执行时模型仍可提交 `finish`，并由同一套完成规则判定。官方评分维持独立。

## 离线回归

- Evaluation 定向回归（`test_swebench_adapter.py`、`test_evaluation_checks.py`、`test_check_quality.py`）49 项通过、17 个子用例通过。覆盖 500,000 token 临界值、重试后实报超估算、计划完成门禁、失败后结构化报告、执行与收尾工具权限。
- 扩展回归另含任务生命周期、工具、工作区和 Provider 重试，共 101 项通过、76 个子用例通过、2 项失败。失败均在 `test_tools.py`，对消息总数和最后一条消息的位置写死了预期。用 Django 旧轮次归档源码复跑，两项在相同行以相同值失败，未修改这两项预期。

## 剩余验证

复验修正了重试后回退结算可能丢掉高额实报用量的路径。保守结算会取原请求估算和已报告用量下界加未报告尝试估算两者中的较大值。

预算准入通过精确边界验证。Provider 实际消耗严格不超过 500,000 的要求未通过。API 返回实际用量前，客户端只能按 tokenizer 和模板开销估算。例如，模拟实报偏差后结算达到 500,188，系统终止并挡住后续请求，已发生的用量无法撤回。下一次真实单题可核对紧凑请求实际用量，并观察新增调试机会能否转化为官方通过。要对实耗提供严格保证，仍需 Provider 侧总量上限或经确认的输入计量上界。
