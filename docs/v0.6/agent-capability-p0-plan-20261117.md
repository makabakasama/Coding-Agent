# Agent 读、改、运行能力改进计划

目标是让模型能够读取相关代码、完成修改、获得真实反馈并继续定位。依据 [15 题记录](swe-lite-15-task-results-20261117.md) 和各轮原始轨迹制定。本轮为方案，未修改执行逻辑、运行测试或模型。

## 已核对的问题

- 15 题官方通过 3、未通过 8、空补丁未评分 3、基线异常未运行模型 1。三道官方通过题最终均报告 incomplete，模型自报与官方成绩需要各自保留。
- Django 的 11019、13220、15320、16379 四题，开发检查 command.json 明确执行 testbed Python 的 `-m pytest`，test-output.txt 出现 `No module named pytest`。16379 同时官方通过。当前 check_runner 只对 SymPy 特殊处理，其余仓库使用 pytest。第四道 Django 14155 的现有检查为临时脚本，不能计入这四次缺 pytest。
- SymPy 14817 三次读取返回 File missing or too large。core/tools.py 的 read_file 即使只取少量行也拒绝超过 800000 字节的文件。
  后续核对发现这三次请求的路径不存在，不能将该案例归因为文件过大；800000 字节限制本身仍存在于当时代码。见 [复测记录](p0-model-retest-result-20261117.md)。
- Flask 5063 与 scikit-learn 11281 均出现编辑行号超出快照范围；此前 Max 对照的补丁破坏 Python 语法。版本快照可阻止旧内容覆盖，编辑成功本身不证明语法成立。
- pytest 11148 将问题示例中的 pmxbot 当作必须提供的仓库，空补丁退出；Django 12113 未建立根因，SymPy 12419 复现后未定位，均未产生补丁。
- 本批三道官方通过题均自报 incomplete。交接轨迹汇总显示 14 轮最后请求均为 normal，不能将结束归因于 finish-only；本轮只逐项复核上述相关轨迹，不额外声称已经重新审计全部请求。
- Sphinx 10451 的官方基线报告列出控制失败，而原始输出为 2 failed、80 passed。需单独核对运行脚本、日志格式和评分解析；当前不能算模型失败。

## P0-A 让开发检查能运行

按仓库提供显式测试执行配置，确定容器内解释器、原生测试入口、测试目标到命令的映射和必要配置。优先实现 Django 原生测试入口与 SymPy 既有入口，其他仓库保留当前 pytest 路径并做可用性检查，避免误报。配置来自固定仓库和评测准备，不暴露隐藏评分测试。准备阶段记录解释器、命令及依赖检查结果，入口不可用时提供清晰原因；不自行安装 pytest 来掩盖入口不匹配。

复用容器检查和现有单容器锁、资源限制、超时、输出归档与清理逻辑。开发镜像以官方评分基础环境为依据，源码固定到同一 G 并只应用当前补丁。保持现有 run_tests 调用形状与临时脚本行为。无法映射文件目标时明确提示可用入口，不把未执行当作通过或目标失败。

## P0-B 让模型能读和安全修改

大文件按行区间流式读取，限制返回行数和字符数；完整文件以流式哈希校验版本，避免把整个文件驻留内存。编辑仍验证整个文件版本，保留路径权限、UTF-8/BOM、换行及快照范围。实现前先确认现有调用方对 total_lines、内容、文件快照和并发修改的依赖；超长单行及文件变化要明确反馈。大文件编辑使用有界临时材料和原子替换，失败不破坏原文件。

每次成功编辑继续返回局部 diff，并针对 Python 在目标兼容解释器可用时提供轻量语法诊断，报告文件、行列和原因；解释器不可用时标记未检查。多步编辑允许暂时不完整，诊断作为反馈而非自动回滚或强制门禁。最终测试仍由任务运行环境执行。行号替换继续保留，另在方案与轨迹中比较上下文替换的失败率和成本，再决定是否新增格式。

## 依赖与实施顺序

先盘点 Django 固定版本的原生测试目标映射与镜像解释器，再实现 P0-A。随后完成大文件读取与快照兼容，最后接入目标环境语法反馈。共享设施和历史轨迹保持兼容。Sphinx 报告解析单独调查，不将其并入模型失败样本。

| 验收 | 要验证的结果 |
| --- | --- |
| 原生测试入口 | Django 固定任务文件能映射到正确测试标签，配置、解释器与导入路径可追溯；缺依赖/目标不可用明确反馈 |
| 检查兼容 | SymPy、临时脚本及现有 pytest 项目维持现有调用语义；失败、超时、异常清理和单容器串行保持有效 |
| 大文件 | 可读超过 800 KB 的指定行，控制内存；BOM、CRLF、超长行、无末尾换行与并发修改可正确处理 |
| 编辑反馈 | 越界/过期快照不改文件；产生语法错误后准确反馈并允许下一步修复；目标解释器不可用时不伪报通过 |
| 证据边界 | 不向 Agent 提供隐藏测试、标准答案或历史诊断；官方评分与开发检查分别留存 |
| 效果 | 先以固定失败类型做工程回归，再固定模型、任务、权限和预算做当前/改进框架小样本对照；成熟框架和模型对照另定预算 |

## 后续方向
