# Harness v0.6-reliability.1 离线验收

2026-11-19。行为验证修复通过离线验收。收尾软提醒完成影子回放，默认执行流程保持原样。未启动 Docker、付费模型或官方评分。`v0.6-reliability.1` 是工作区版本标识，已有 RC1 `2f3b5139` 和历史 P2 `1c06d2c1` 的归档哈希均通过复核。

## 退出码与行为验证

本机和容器共用 `repo_agent/core/check_execution.py`。旧版把临时 Python 脚本的退出码 0 直接转成 `passed=true`，再由分类器反馈 `PASS`。新版本保留 `execution.status=exited`、退出码和日志。缺少可信验证证据的脚本使用 `TEST_EVIDENCE_UNAVAILABLE`，检查分类为 `UNKNOWN`。

| 实际本机子进程 | 修改前 | 修改后 |
| --- | --- | --- |
| 只定义包含 `assert False` 的函数 | 退出 0，`PASS` | 退出 0，`UNKNOWN`，无断言已执行的证据 |
| 显式调用同一函数 | 退出 1，断言失败 | 退出 1，保留 `AssertionError`、第 2 行和日志 |
| 显式调用包含 `assert True` 的函数 | 退出 0，`PASS` | 退出 0，`UNKNOWN`，原始脚本未提供逐项成功证据 |
| 通过测试运行器执行成功的命名用例 | 有效 JUnit 或逐项文本时通过 | 真实 JUnit 用例通过，命名用例证据仍支持 `VERIFIED` |

87 项回归和 12 个子检查通过。覆盖真实 Python 脚本、真实本机 JUnit、已有有效逐项文本结果、零用例、全跳过、报告冲突、P1 检查证据失效和异常保留、P2.2 需求映射及 Oracle、收尾预算与任务交付。首次 pytest 使用系统默认临时目录时遇到访问拒绝，改用工作区内隔离目录后完成同一套回归。容器路径通过共享解释器和既有容器桩测试核对。

限制是普通 Python 直跑没有逐项成功回执。即使脚本实际运行了断言，只要只有正常退出和原始日志，仍只能记为执行成功。旧批次有 8 条此类 `PASS` 反馈。轨迹里的退出码只能确认这些命令退出 0，其中实际执行了多少断言需要分别核对。

## 一次性收尾提醒影子回放

在当前完成规则接受 `finish` 的位置做影子判断。最近一次成功的业务修改之后，需要出现可信且仍有效的失败证据。新的业务修改使旧证据失效，只有同一目标、测试定义和环境下的可靠通过能解除同版本的失败。同目标退出 0、其他目标通过、基线失败、启动异常和未确认的 Oracle 均不足以改变判断。

预算使用此次普通请求的估算、追加提醒开销和已保留的紧凑收尾额度，另外检查上下文、剩余决策与软超时。`finish-only` 不进入提醒。轨迹回放复用历史请求估算，结果属于本地预算估算。

符合条件时，提醒应说明失败目标和证据，并允许模型继续一个具体、授权且安全的下一步，或带着阻塞原因直接 `finish`。每轮最多一次。用户要求停止、继续不安全、没有可行下一步或已经提醒时，应直接接受收尾。若无法从状态核实是否有可行下一步，影子回放只登记候选，保留当前收尾。上述判断没有接入生产。

回放固定 RC1 / P2 批次的 14 条已归档轨迹。现有规则拒绝的 8 次收尾请求由原规则负责。14 次被接受的收尾中，严格规则筛出 1 个候选，9 次无当前可信失败，4 次无业务修改。放宽到临时脚本的运行异常后，候选增加到 2 个。另有 17 项合成断言覆盖同目标解除、无关检查或不同环境不能解除、未知证据、基线失败、额度不足及直接结束条件。

| 回放候选 | 轨迹依据 | 误报风险 |
| --- | --- | --- |
| Django 16229 RC1 | 第 7 步修改，第 10 步仓库测试出现基线通过、候选失败的断言，第 14 步 `finish(incomplete)`。本地剩余 275,737 Tokens，估算下一步加收尾需 38,309 | 回归证据可靠。模型已说明已有测试的兼容约束、测试文件编辑权限以及 PostgreSQL 检查全跳过。轨迹无法确认授权范围内还有可行修复 |
| scikit-learn 12471 RC1（宽松口径） | 第 8 步修改，第 11 步临时复现仍抛异常，第 12 步 `finish(incomplete)`。本地剩余 399,737 Tokens，估算需要 30,005 | 异常确实发生，基线也失败，当前只有过程异常证据，尚未确认有可信的独立断言。放宽触发会纳入类似的复现或环境偏差 |

**决策**：行为验证修复可以保留。当前没有足够证据为收尾提醒启动付费 A/B。唯一严格候选的可修复性未确认，回放只能验证筛选和退出规则，无法评估提醒是否产生新的修复闭环、提高官方通过率或增加成本。评分器不可变性继续作为独立基础设施事项。
