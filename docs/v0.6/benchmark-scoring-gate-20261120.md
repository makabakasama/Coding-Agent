# Benchmark 评分可靠性验收

2026-11-20，`scoring-gate.1` 工程验收 **PASS**。生产门禁及无模型补评已验证。冻结记录保存评分源码、运行环境和验收产物的 SHA256。既有 RC1 和 P2 的提交及归档包哈希通过复核。

## 生产流程

1. Preflight 按注册哈希复制评分启动器、容器生命周期和镜像供应模块，进行真实独立 Python 进程导入检查。评分解释器固定为已核验的 Conda 可执行文件，记录 Python、SWE-bench 5.0.2、依赖版本及安装记录、解释器和关键包文件哈希。评分容器使用注册的镜像 ID。
2. 每次派发前核对运行环境。模型结束后记录候选补丁、运行记录及 Token 账本引用，再启动官方评分。Git 安全授权通过子进程环境限定到注册且已核验的源仓库。
3. 评分进程从冻结副本启动。运行期间检查副本和控制文件，发现漂移即隔离该次成绩，并等待当前容器正常清理。评分结束后验证补丁、镜像、源码 tree、评分器指纹和原始报告与测试日志的一致性。
4. 启动失败、文件漂移或成绩不可验证时，保存 `UNSCORED` 结果并写入 `scoring-pause.json`。队列退出码为 2，后续 arm 不产生付费请求。重启同一队列继续保留暂停，已有补丁可经 `benchmark regrade` 独立补评。空补丁按原规则记为未评分。

## 剩余风险

评分代码作为独立快照运行，评测容器使用不可变镜像 ID。宿主 Conda 环境通过版本和哈希核验锁定，仍依赖本机文件系统和 Docker 引擎。运行中固定间隔检查评分文件，宿主依赖在执行前后复核，极短的改动后恢复和未纳入哈希的系统组件变化仍可能漏检。进程或 Docker 异常中断可能需要先核对容器清理，已有暂停会继续阻止付费派发。真实补评分属两个仓库，付费派发边界使用无模型模拟验证。
