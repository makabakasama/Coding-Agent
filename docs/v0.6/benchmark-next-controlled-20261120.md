## 冻结条件与启动门禁

1. 在预检时从项目 `.env` 读取模型、配置档与 Provider 地址指纹。两组采用相同配置，同一次注册内保持一致。每题新建独立工作区，固定基准提交及 tree、权限、开发测试入口、开发镜像和官方有效评分镜像 ID。每题的两份补丁用同一个已核验的有效评分镜像。
2. 采用同一 500K 客户端账本、50 次决策、30 分钟软超时、128K 上下文、8,192 普通输出上限。开发检查与评分时限、传输重试和权限策略以同一注册快照固定。保持宿主资源检测、单容器串行与 1 GiB 容器限制。
3. 启用 `scoring-gate.1`。核对已冻结源码索引和评分环境指纹，运行导入探测和无模型基线。确认基线能识别目标未通过，控制测试结果和评分链路可复核。发布绑定了评分运行时 SHA256 的 release 后才安排 6 次模型运行。评分故障先停队列，候选补丁优先走独立补评。
4. 模型只接收公开题面、固定仓库和开发反馈。官方评分输入、基准补丁和评分结果明细留在评分侧。

## 指标与重复规则

- 首次运行是主分析。报告官方 PASS、FAIL、UNSCORED、NO_SUBMISSION、未运行，以及登记总数、有效评分次数和严格配对胜负。用量以实际 Provider 回执为主，并列未知用量、每次成功的摊销 Tokens 和耗时。
- 主要行为指标为仅退出 0 被错误标为 PASS 的次数、命名用例证据保留率、失效证据复用、修改后的可证实调试闭环、收尾类型及模型自报。报告原始脚本使用次数作为分母。若两组均没有触发该场景，试验只说明其他已观测指标。
- 正式首次结果归档后，若出现双边有效成绩不一致，或双方同分但实报 Token 最大值至少为最小值的 1.5 倍，按原登记顺序优先复核一道。使用相同版本和预算完整重跑一对，另行授权，最高新增 1,000,000 名义计账 Tokens。已提交补丁的评分设施恢复只重评原补丁。复核结果与首次运行分开报告。
