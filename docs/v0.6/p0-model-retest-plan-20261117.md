# P0 受影响任务复测计划

从已有 15 题固定选取两题，每题一次，观察原有工具障碍是否消失及官方结果。选题依据是此前具体工具失败，不按预期是否容易成功选择。

| 任务 | 原有障碍 | 复测观察 |
| --- | --- | --- |
| django__django-11019 | 开发检查尝试 pytest，testbed 中缺少该模块，官方未通过 | 模型是否调用原生测试入口、实际测试是否执行，以及反馈后是否继续修改和官方结果 |
| sympy__sympy-14817 | 三次大文件读取被拒，官方未通过 | 大文件读取及需要时编辑是否成功、版本核对是否生效，以及模型后续行为和官方结果 |

两题都是已知开发案例。此前运行是历史参照，代码及环境随 P0 改动，单次结果不能证明改动带来稳定提升。若模型未触发对应工具，记录为未观察到，不推断通过或失败。语法提示仅在模型产生相应编辑或调用检查时记录，不能以没有触发来宣称已验证。

固定同一 gpt-6-luna、原题 G 与任务输入、官方基线、标准提示及原工具权限。每题最多 50 次决策、累计账本 500000 token、软超时 1800 秒、上下文 128000、输出上限 8192。两题总计账上限 1000000 token，实际用量按 Provider 报告和预算账本分别留存，费用未估算；估算不等于服务端硬收费上限。每题新副本，保留原轨迹，模型一次，失败不自动重跑。

两题依次运行，开发检查和官方评分共享现有串行容器锁，每容器资源限制及 WSL 8 GB 上限沿用。启动前确认 Docker 数据在 D 盘、容器无残留、空间足够；完成后检查清理。评分使用已验收的相应 G/R 基线，记录复用与环境身份。隐藏测试与失败轨迹不传给模型。

每题分别记录工具观察、补丁、开发检查、模型结论、官方结果、用量和耗时。复测结束后先分析，不自动扩大评测或调整模型。大文件最终哈希核对到替换之间的外部修改窗口由用户接受，作为已知限制保留。

本计划未启动模型或测试。
