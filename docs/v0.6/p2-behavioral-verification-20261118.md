# P2 行为验证离线验收

## 设计

原来的 `run_tests.review` 已能检查题面引用、测试行号和固定仓库引用。最终汇总只有检查结果、仓库回归和待审查状态，无法说明哪个需求场景得到了执行证据。

P2 沿用同一份 `review.criteria`。每项对应一个场景和预期，可标注题面示例、边界、组合或兼容性。用例级结果需要运行器确认目标身份，确认失败时需要断言位置对应。对成功用例，自动核对限于直接执行的、预期可与题面或固定仓库关联的简单断言。一个断言被用来代表多个场景时，系统保守地标为缺证据。

| 状态 | 条件 |
| --- | --- |
| `VERIFIED` | 已确认命名用例通过，场景引用了其中的具体断言，预期值可追溯 |
| `FAILED` | 已定位到映射的断言失败，预期值可追溯 |
| `NOT_COVERED` | 缺少映射、可识别的逐项执行证据或可核对的断言联系 |
| `BLOCKED` | 测试结果不可用、已执行但预期仍是推测，或旧预期与题面之间的潜在冲突待判断 |

冲突项复用题面引文和固定仓库引文，附上兼容性分析。冲突状态保留不确定性，测试实际通过或失败的事实仍单独记录。完整记录保存测试目标、行号、检查 ID、测试定义摘要、场景、预期和实际结果。失败值沿用 P1 的运行器差异，无法取值时标记 unavailable。

行为覆盖接入共享检查，沿用 P1 的候选版本、执行环境和脚本依赖校验。模型收到累计计数和本次检查的逐项结论。完整报告保存在检查归档和评测开发报告中。`VERIFIED` 的范围为已声明场景，项目级完成、官方评分及语义覆盖均由原有字段表达。命名选择复用原测试入口，Django 与 pytest 在显式单用例时输出身份，SymPy 复用 P1 的确认。

## 两条开发轨迹重放

依据原公开题面、固定提交中的测试源码、留存的开发执行记录，补录人工场景映射。重放脚本核对测试文件摘要，并校验规定的输出分类。场景由本轮分析补录，执行来自旧记录。

| 题目 | 逐项结果 | 能从公开证据得出的结论 |
| --- | --- | --- |
| Django 11019 | 3 `NOT_COVERED`，1 `BLOCKED` | 17 项仓库回归仍有效。公开三路合并用例与临时脚本覆盖了特定依赖图。脚本还检查了排列与分组、CSS、重复资源和环，但排列仍共享同一组约束，没有单独确认独立分支的顺序策略。既有日志缺少逐场景证明。 |
| SymPy 14817 | 3 `VERIFIED`，2 `NOT_COVERED`，1 `BLOCKED` | P1 单独运行的公开用例确认三条独立断言，分别是单个负矩阵乘积、普通矩阵相减、两个负乘积加一个正乘积的一个具体组合。旧临时脚本第 24 行确实失败，分隔符预期来自脚本推断，因此场景保留为 `BLOCKED`。题面 `y*` 与第 26 行矩阵幂未取得逐项通过证据。 |

Django 固定仓库 `test_construction` 的元组断言针对直接用元组构造的单个 `Media`。题面描述合并后的脚本顺序，也展示了旧执行结果的列表形式。由这两处材料无法确定一个通用的合并后 tuple/list 契约，亦无法确认它们相互冲突。三路合并的公开列表断言仍作为兼容性证据保留。

SymPy 的三条确认仅覆盖固定用例的具体参数。包含特殊标签的多个负乘积、矩阵幂以及 Unicode 等维度仍需各自证据。原有开发回归总体仍为失败。

## Token 开销

以 `o200k_base` 按紧凑 JSON 离线计数。`run_tests` 工具定义从 472 增至 599 token，每个携带该定义的请求增加 127 token。按相同映射比较 P1、P2 反馈，Django 从 663 增至 776，增加 113 token。SymPy 从 998 增至 1136，增加 138 token。两处结果均为反馈增量，随场景数量和保留轮数变化。场景标记及所填冲突说明也计入模型自己的工具参数。增加的模型请求数为零。

## 验收边界

**P2 离线工程验收 PASS。** P2 定向 9 项通过。扩展回归 94 项与 11 个子用例通过，覆盖普通编码执行、进度、预算、测试可靠性和评测适配。两条旧轨迹的逐项分类断言通过。

完整语义仍需阅读题面和断言，错误的场景描述、使用了不合适的公开预期或遗漏的行为维度依然可能导致误判。临时脚本只报告退出码时，即使通过，也不能自动确认具体断言。循环、条件、动态用例和通过变量表示的复杂预期也可能因证据不足被保守标记。P2 没有新增断言级运行追踪。

本轮使用 Conda 定向测试与历史开发材料，未启动 Docker、调用付费模型或运行官方评分。旧轨迹只证明系统更细地识别覆盖，无法证明模型解题成功率提升。

本机留存 `runs/engineering/p2-feedback-tests-412622d3/`，包含 `replay.py`、`replay-result.json` 和 `pytest-acceptance.log`。定向验证还确认了 Windows pytest 输出中包含回车时可识别正确用例及其结果。
