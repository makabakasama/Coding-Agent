# P1 测试反馈可靠性验收

## 修改

- 证据仍关联候选版本、测试定义摘要和执行环境摘要。仓库原生检查不携带临时脚本，临时脚本的增改只影响依赖该脚本库存的记录。进度中的仓库检查引用按同一规则处理。Local runner 使用检出格式读取基线，并核对执行前内容摘要，避免 Windows 换行转换造成伪基线缺失。
- 测试启动、测试体异常和断言失败可从阶段及结构化诊断区分。解析保留最外层异常、链中异常及脚本失败位置。原始日志仍保存在运行材料，反馈提供带边界标记的摘录。实际值与期望值仅在运行器明确输出可识别差异时给出，其余标为 unavailable。
- `run_tests` 可以显式提供最多两项 `independent_targets`，复用各自的测试授权、原生入口和超时，逐个运行并汇总。未执行和失败都会阻止整组通过。SymPy 的文件加函数选择器由固定文件中的唯一匹配和原生输出共同验证。较旧的 `bin/test` 需要把文件参数放在可变参数 `-k` 前面。

## 旧轨迹离线验收

- Django 原生 17/17 的记录和新增临时脚本后的记录具有相同业务补丁、源码树和测试镜像。重放后 17/17 仍为当前证据，完成检查不再因为无关脚本的增添而报证据过期。原版脚本第 33 行触发的 `MediaOrderConflictWarning` 为测试体异常，和 Django 初始化失败分开。
- SymPy 的原版轨迹保留了内层 `SyntaxError` 和外层 `SympifyError`。重放补丁使用已缓存的断网测试镜像，临时脚本第 24 行失败，独立调度的仓库 `test_MatrixSymbol_printing` 实际执行，候选为 1/1 通过，整组为失败。首次执行显示旧版 `-k` 吞了文件参数并运行了三个同名测试，未被系统标为通过。修正参数顺序后只执行了目标文件中一个用例。
- 官方评分同名用例的失败断言与开发检查用例不同。未运行官方评测，也未向 Agent 注入官方隐藏测试。无模型调用。三个缓存回放容器串行运行且均已删除。

本机证据位于 `runs/engineering/p1-feedback-reliability-20261118/replay_20261118-144246_3bfa03ef/`，含轨迹重算和独立测试结果。第一次未确认的选择器回放单独留存。

## 回归与结论

最终定向回归 38 项和 9 个子用例通过。扩展回归覆盖普通任务、进度与交付、评测适配和开发检查，84 项与 19 个子用例通过；其后收紧的原生差异摘录由最终定向回归覆盖。未改 Token Budget、上下文管理、Planner 和模型任务提示词。P1 工程验收 PASS，无需用付费模型补证这次反馈链路修复。

## 剩余边界

普通任务的环境摘要基于解释器和执行配置。可变环境中的依赖若被外部原地替换，尚无包级快照证明；容器评测仍基于不可变镜像。临时脚本未输出实际和预期值时只能反馈断言位置。以上验证确立了反馈与执行行为，尚不能解释为两题官方分数提升或模型能够独立完成修复。
