# B3 前端接入记录

日期为 2026-11-11，北京时间。用户要求进行 B3 并接入前端页面，本轮交付为 Chat 页面及必要的材料读取接口。B3 的 EvalRun 索引、TaskSpec 和开发样本记录/评分通路仍待实施，当前阶段尚未完整收尾。

后续已完成指定离线验收，包含实际无头 Chrome 的 7 个流程场景。最新结果与修正见 [验收记录](chat-acceptance-20261111.md)，以下保留最初接入时的范围与静态检查状态。

## 已接入内容

- 新增 `frontend/chat.js`，通过现有 `app.js` 路由加载。默认首页和侧栏 Chat 进入会话工作区，`#chat/<conversationId>` 可恢复指定会话。布局沿用现有字体和配色，提供宽屏双栏及窄屏适配。
- 会话列表支持分页、刷新、新建与切换。新建时可选已登记项目或不关联项目，当前会话保持纯文本讨论，项目读取按 C1 推进。
- 消息按序号增量读取，支持继续加载和多轮输入。消息以 DOM 文本和围栏代码块展示，模型 HTML 作为文本处理。发送使用 B1 的讨论契约，回复通过 B2 Worker 生成。
- 活动轮锁定新提交，输入草稿仍可编辑。轮次状态、失败原因、用量和请求事件接入详情，用户可从历史消息选择对应轮次。
- 轮询仅使用 GET，正常活动轮每 2 秒查询，空闲会话每 5 秒查询。页面卸载时清理定时器、取消在途请求，并用页面/轮次请求版本挡住晚到响应。
- 草稿与待确认请求保存到当前浏览器标签页的 sessionStorage，并保留内存回退。提交前冻结 clientRequestId、expectedRevision 和正文，网络/服务端未知结果保留原请求，用户点击重试时使用同一载荷。明确的 4xx 拒绝保留草稿，重新查询后允许新提交。

会话创建只保存会话元数据，发送消息会启动真实配置下的模型请求。进入已有会话、轮询和读取材料均为只读操作。完整交互仍依赖 API 与 Worker 使用相同数据库和数据目录配置。

## 材料接口与旧记录兼容

新增 GET `/api/conversations/<id>/turns/<turnId>/artifacts/<artifactId>?offset=0&limit=16000`。

接口只接受 context、request、response、reply、trace、result 六类已登记附件，先核对会话和轮次，再检查相对路径、领取 ID、文件类型和登记 SHA256。逐块读取和解码文件，仅保存本页内容，支持按 Unicode 字符分页。文件缺失、链接路径或哈希变化分别返回错误。

页面展示已保存的上下文、模型请求/响应、轨迹与结果。每页核对返回的轮次、游标、完整性和哈希，失败时保留此前页与游标，便于重试。材料经过 B2 的凭据值脱敏，文件哈希核对仅证明与登记材料一致。

会话记录增加 latestTurnId，用于刷新后定位最后一轮的完成或失败记录。旧记录未包含该字段时，GET 从本会话最后一条用户消息恢复该索引，无需迁移原记录。原任务与实验历史入口继续沿用现有路由。
