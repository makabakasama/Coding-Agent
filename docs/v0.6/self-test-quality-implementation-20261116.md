## 当前实现

Evaluation 的 run_tests 增加可选 review 参数，记录检查用途、任务原文摘录、场景、预期结果、测试行号及假设。程序核对摘录出自所给任务、行号属于该次测试，并保存测试哈希。字段中的语义覆盖解释保留模型自报性质。原 run_tests(target=...) 调用继续可用，缺少 review 会在结果中提示。

任务提示引导当前模型在正常循环核对需求与测试的关系，选择相关既有回归，说明未覆盖范围。输入限定为任务及固定工作副本，没有新增联网工具或额外模型请求。

临时检查默认按缺陷回归处理，分别在固定 G 与 G+P 执行同一份脚本。可通过 review.purpose=control 声明控制检查，只运行当前版本。已有仓库测试默认按控制检查执行，也可明确选择前后对照。

为隔离测试产生的文件、进程和缓存，前后对照采用两个依次创建的容器，前一个删除后才启动后一个，复用全局进程锁与现有资源限制。两阶段共享原有检查时间预算，单次 run_tests 的总容器创建数会增加。容器并发仍为 1。每阶段输出及归档、源码身份、补丁与检查快照均保留。

只有识别到脚本断言失败或测试框架明确失败，才记录为检查失败。导入错误、其他脚本异常、超时和终止等记录为 unknown。前失败后通过标记为版本差异，targetReproduced 保留未知，无法从退出码推断是否复现任务中的目标缺陷。

## 反馈与验证等级

run_tests 返回候选结果、修复前输出及结果、需求映射和验证摘要。检查记录按目标、业务补丁及全部临时脚本清单哈希关联。修改业务或脚本后，旧结果不再属于当前版本。

验证摘要记录 needs_review、developer_check_failed、verification_incomplete。即使所有开发检查通过，仍保留 needs_review。相关既有回归由 Agent 通过现有文件目标选择执行，摘要报告选定文件范围及缺失记录，程序无法自动确认文件选择完整。

同版本某目标的最新失败或基础设施异常不会被另一目标通过覆盖，完成校验反馈对应事实并允许同一循环继续修复。需求核对缺失及假设本身不增加语义完成拦截。

attempt.json 新增 developerVerification。官方 Grade 增加 external_pass、external_fail 或 verification_incomplete 摘要，并保留既有来源和环境未独立核验字段。模型自报状态、开发验证和官方成绩继续分别保存，历史记录读取方式沿用。
