## 已实现范围

| 范围 | 当前行为 | 边界 |
| --- | --- | --- |
| 输入与目标 | 路径加描述；Git 根目录/子目录、普通目录、单文件；高级契约入口保留 | 支持的源码和文本类型；不是任意二进制编辑器 |
| 默认任务 | 简化入口默认 direct、50 步、不测试；完整契约省略模式仍为 worktree | 直接模式修改当前文件，包含未提交内容；测试需明确开启并指定目标 |
| 调度与 Worker | PostgreSQL 幂等入队、事务领取、心跳、单池锁；独立进程默认 3 个线程槽位 | API 与 Worker 共用本机材料；不是跨机器分布式执行，未知任务不自动重跑 |
| 直接修改 | 保存基线、生成实际 Diff、执行后哈希核对、显式撤回 | 后续编辑导致冲突时拒绝整批撤回；缺少历史证据时不能安全撤回 |
| 任务生命周期 | 回收站、恢复、确认后彻底删除，清理中断可核实/继续 | 删除记录不撤回源码；永久清除会删除该轮日志、基线、材料及符合身份条件的 worktree |
| 完成状态 | finish 附 outcome/evidence；无编辑的修改任务不能直接报告 completed；结果单独展示 completion | 仍是模型报告及程序规则，不等于需求正确性或独立验收 |
| 缓存和连接 | Redis 读取缓存、失效与故障回退；PostgreSQL 连接池 | Redis 不负责排队，缓存命中不替代关键操作的数据库校验；无降本/性能提升量化结论 |
| 开发运行 | API/Worker 分开启动、日志、--reload | Worker 重载等待在途任务，不是模型断点恢复 |
| 实验兼容 | 历史 G/R/P、报告与附件浏览、显式历史导入 | 旧成功轮不自动升级为 V0.4 验收；历史原件不因文档更新改写 |

## 数据与执行链路

```text
网页 / 任务 CLI → HTTP 服务 → PostgreSQL 任务与调度记录
                                  ↓
                         独立 Worker 池
                                  ↓
                   原有 Agent / Provider / 工具
                                  ↓
                目标文件 + 运行轨迹 + 检查 + 结果
```

当前 HTTP 实现是 Python 标准库，不是 FastAPI。Worker 内为线程池，不是每个槽位一个隔离进程。Git worktree 仅提供文件副本，direct 使用当前本机目标；两者都没有 Docker 执行沙箱。

`tasks`/`task_runs` 保存需求和轮次，`task_dispatch` 保存队列/领取/心跳/终止原因，`task_trash` 保存回收站状态。执行结果、事件、基线、Diff 和撤回状态继续有文件材料。导入历史可以在数据库保存材料快照，不表示所有新运行材料实时完整备份到了数据库。

## 已知限制与后续优先级

- 单机、单用户、同一数据目录单 Worker 池；并发槽位不构成吞吐量或稳定性基准。
- 缺少容器执行隔离、完整资源限制、主动停止任务和模型断点续跑。Worker 停止领取并排空任务不等于取消任务。
- 普通任务检查、模型完成状态与独立 G/R/P 验收分开；默认不测试的任务尤其不能仅凭总结判断正确。
- 测试工具仍围绕 pytest，尚无通用多语言构建/测试流程；上下文保留全部对话，没有已验证的压缩与成本优化。
- 自动撤回依赖完整基线和执行后哈希；外部并发修改不能被工作台锁完全控制。
- 真实 PostgreSQL/Redis 集成、实际页面和真实需求交付需按版本保存证据；新机器环境复建和完整实验重放仍需补充。

下一阶段以真实需求交付和失败轨迹驱动改进，优先完善执行边界与控制，不以增加 UI 功能数量替代能力评测。
